# 质量评审模式（给已有 skill 打分，不重做）

触发条件：用户提供一个已有 skill（目录路径）并要求"评审""体检""打分""看看这个 skill 行不行"。**评审只诊断不重写**——除非用户明确要求修复。

## 执行流程

1. **机器校验先行**：跑 `python "<knowledge-distill目录>/scripts/validate_output.py" "<被评skill目录>"`（pack 产物追加 `--pack`），结果作为格式分的客观依据。
2. **按七个维度人工评分**（满分 100），每项打分必须引用产物中的具体行文作为证据。
3. **输出评审报告**（格式见下）。

## 评分维度

| 维度 | 分值 | 评分依据 |
|---|---|---|
| 证据纪律 | 25 | single 根文件或 pack 每个被路由子能力的证据账本存在且逐条挂定位+合法置信标签（Observed/Strong/Tentative）；unknown 独立成节而非混入结论；根文件与 references/ 引用均 ≤150 字（英文 ≤100 词） |
| 可触发性 | 18 | description 含明确触发词（中英双写更佳）与排除场景；有分诊表（信号→路由）；触发条件是可观察信号而非抽象描述 |
| 反例与停止条件 | 13 | ≥1 条"当 X 时不要/退回…"的 fallback；停止条件明确可判定 |
| 格式合规 | 12 | frontmatter 完整、name 与目录名一致、validate_output.py 退出码 0、无断链 |
| 可执行性 | 16 | 照着产物能不能真跑通：命令与路径在本平台可用、无平台专有接口硬依赖（如 listSkills）、缺依赖处给了安装方式而非裸引用、安装与验证步骤可实际执行 |
| 渐进披露 | 8 | 深度内容是否合理拆到 references/；SKILL.md 是否撑爆上下文（>400 行扣分） |
| 非摘要性 | 8 | 规则是"条件→动作"格式；删掉原始素材后产物仍能独立指导执行 |

分值合计 100。可执行性单列，是因为前三类问题（示例冒充证据、平台专有命令、工具链裸引用）全部出在这一维，之前的六维度里无处归因。

## 评审报告格式

```markdown
## 总评
<分数>/100 — <一句话定性：可安装 / 需修改 / 建议重做>

## 分项得分
| 维度 | 得分 | 关键证据 |
|---|---|---|

## P0 问题（阻断）
<不修就不能用的项，每条给出产物中的具体位置>

## P1 建议
<改善质量但不阻断的项>

## 修改建议
<逐条给出可直接落地的改法，只指路不动手>
```

## 边界与 fallback

- 当被评对象不是本 skill 的产物时：按七维度照常评审，但注明"该产物未经证据纪律约束"并在证据纪律项如实给低分——不为其虚构证据结构。判定时 single 查根文件账本，pack 查分诊表引用的子能力账本；pack 路由入口没有根账本不属于缺失。
- 当用户要求"边评审边修"时：先出完整报告再改，不允许边评边改掩盖原始问题。
- 评审自身不受评（不用 review-mode 评 review-mode）。
