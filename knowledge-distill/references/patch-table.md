# 补丁 E：表格 / 数据素材

适用素材：Excel、CSV、TSV、数据集导出、数据库 dump、BI 仪表盘导出。

## 提取维度（五路并行）

1. **模式发现**：列间关系、时间趋势、分组差异——只提取**可复现的计算口径**（怎么算出来的），不接受只给结论不给口径。
2. **口径与约束**：字段含义、单位、空值/异常值的处理规则——这些决定结论是否可迁移。
3. **计算规则**：把重复出现的手工计算抽成可执行公式 / SQL / DuckDB 查询，标注适用前提（如"仅当分组键唯一时"）。
4. **数据质量坑**：编码问题、脏数据模式（重复行、格式漂移、单位混用）→ 写成 fallback 分支。
5. **判断阈值**：业务规则中的数值边界（如"逾期 >30 天转催收"）→ 逐条转"条件→动作"。

## 额外要求

- 定位格式统一为 **sheet 名 + 单元格范围/行列号**（如 `Sheet1!B3:F87`、`CSV 行 120-135`），不接受"大概是中间那段"。
- 大表（>200 行）结论必须用 `pandas` / `DuckDB` 对**原始文件**实算验证后才能标 Observed；只凭抽样目测的结论标 Tentative。实算环境与最小样例验证见 `bootstrap.md`。
- 计算规则必须附带"用样本数据算一遍"的验证结果与预期值，算不上的规则标 unknown 并给复算探针。
- 字段含义拿不准时记 unknown，禁止按列名望文生义填充业务含义。
- 聚合类结论（均值/占比）必须写明过滤条件与口径，防止口径漂移导致结论不可复现。

## 与总纲的衔接

- 阶段 1 按五路并行产出候选，定位为 sheet+范围。
- 阶段 2 中：判断阈值 → 路由判断；数据质量坑 → 放弃判断（fallback）；模式发现的适用前提 → 结束判断素材。
- 阶段 3 产物建议带 scripts/（确定性计算脚本），避免把长查询塞进 SKILL.md。
