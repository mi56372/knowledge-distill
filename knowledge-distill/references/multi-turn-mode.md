# 多轮模式（素材较大时改用这个）

当素材过大、单轮跑不完总纲的五阶段流程时，把总纲最后一句（"现在开始"）替换为：

```
本次只执行阶段 0 与阶段 1，输出候选单元清单（含定位）后停止，等我确认筛选结果。
后续我会用"继续阶段 2""继续阶段 3"逐轮推进。每轮开头先复述上一轮结论的编号，
保证可追溯；跨轮不得修改已确认条目的定位与置信标签。
```

## 状态文件（distill-state.md）

多轮蒸馏必须在 OUTPUT_PATH 维护 `distill-state.md`，格式：

```markdown
# distill-state
- 素材标识: <路径/链接/书名>
- 素材类型: <软件/代码 | 视频 | 图片 | 书籍/文档>
- TARGET_USE: <用途；未确认不得进入阶段 1>
- 当前阶段: <0..4 或 done>
- 已确认结论: 编号 + 定位 + 置信标签（只增不改，修正另起条目）
- 淘汰清单: 编号 + 淘汰理由
- 待办: 下一阶段编号
```

- 每轮结束时立即更新。
- 新一轮开头先读本文件续跑，不从头重来。
- 已确认条目的定位与置信标签跨轮不得修改——发现先前定位有误时，新增一条修正记录并注明原因。

## 多轮纪律

- 每轮只推进一个阶段，不跳跃。
- 每轮开头复述上一轮已确认结论的编号，保证可追溯。
- 跨轮不得修改已确认条目的定位与置信标签——发现先前定位有误时，新增一条修正记录并注明原因，不改写历史条目。
- 长文档分批时维护跨批次全局术语表与去重表（见 patch-document.md），防止同一原则被重复收录。
- 视频素材跨批次转写时，四路对齐信息（口播/画面/OCR/时间戳）必须保持同帧对齐后再入库。

## 与 reverse-distill 的分工

- reverse-distill 处理"逆向会话记录 → skill"，输入是证据账本。
- 本 skill（knowledge-distill）处理"原始素材 → skill"，输入是视频/图片/书籍/代码。
- 两者共用同一套证据纪律。**仅当当前环境确实安装了 reverse-distill 时**，才可在阶段 1 之后把候选单元交给它的判断时刻提取流程做规则化；未安装时由本 skill 自己的阶段 2 完成，不要假装调用一个不存在的 skill。
