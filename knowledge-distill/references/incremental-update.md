# 增量更新模式（源素材变化后更新已蒸馏 skill）

触发条件：用户提供一个**已由本 skill 蒸馏出的产物**，并说"素材更新了""重新蒸馏""同步一下最新版"，或指出产物某条结论已过时。

## 执行流程（按序，不得跳步）

| 步骤 | 动作 | 证据要求 |
|---|---|---|
| 1 建立基线 | single 读根 `SKILL.md` 的证据账本；pack 按分诊表逐个读取被路由子能力的证据账本（路由入口无根账本属于正常结构）。两者都再读 `distill-state.md`（若在），列出全部旧结论及其定位 | 每条旧结论必须有编号；pack 结论编号同时记录子能力路径 |
| 2 素材 diff | 对源素材重新做阶段 0 体检 + 定向扫描，找出**新增 / 修改 / 删除**的部分；不做全量重提 | 每处变化标注定位 |
| 3 影响分析 | 逐条旧结论三分类：**保留**（定位仍有效、内容未变）/ **需更新**（定位漂移或内容变化）/ **失效**（素材已删除该内容） | 每条判定挂新定位 |
| 4 事务性更新 | 只改受影响条目：需更新的重写规则并重新取证，失效的移入"已失效"区并注明原因；保留条目一字不动 | 新规则挂定位+置信标签 |
| 5 版本演进 | 产物 version minor+1（如 1.0.0 → 1.1.0），更新记录写入产物末尾 CHANGELOG 小节：日期 + 变更条目编号 + 原因 | — |
| 6 重验证 | 跑 `python "<knowledge-distill目录>/scripts/validate_output.py" "<产物目录>"`（pack 产物追加 `--pack`）+ 4 条冒烟测试 | 校验退出码必须为 0 |
| 7 重装生效 | 若该产物已安装到扫描目录：经用户确认后 `python "<knowledge-distill目录>/scripts/install_skill.py" "<产物目录>" "<已安装目录>" --replace`（pack 产物追加 `--pack`），再对目标目录复跑一次校验（pack 产物同样追加 `--pack`） | 输出 `INSTALLED`，目标目录校验退出码 0；只改源目录不重装 = 触发到的还是旧规则 |

## 更新纪律

- 不重写未受影响的条目——增量更新的价值就在于最小改动。
- 更新不得凭"感觉内容变了"改写——每处变更必须指向素材中的新定位。
- 置信标签只在重新取证后才能升降；仅因定位漂移做格式修正的不动置信标签。
- 若 `distill-state.md` 缺失，且 single 根文件无证据账本、pack 所有被路由子能力均无证据账本：判定"无基线"，退回全量重蒸馏（走 single 流程），不做伪增量。

## fallback

- 当 single 根文件无证据账本，或 pack 所有被路由子能力均无证据账本，且没有可用状态基线时：不要硬做增量——它不是本 skill 的产物或已严重退化，告知用户需全量重蒸。
- 当受影响的旧结论数 / 旧结论总数 > 50%，或源素材中被替换的章节、文件超过一半（按条目计）时：不要逐条修补——全量重蒸馏更可靠，向用户说明原因后走 single 流程。
